# Python-decoder golden videos

These are **representative cat-mode videos that the Python server-side decoder
(`web_demo/app.py::_decode_cat_video`) actually decodes**, captured from the
real browser encode pipeline.

## Why these exist (and how they differ from `../`)

The videos in `tests/golden/*.webm` are fixtures for the **JavaScript** in-browser
decoder (exercised by `tests/run_golden_test.py` via headless Chrome). They are
generated by `examples/golden-video-generator.html` and are **not** decodable by
the Python decoder — its eye-state/preamble model differs from that generator's
waveform. That is by design; they target a different decoder.

The Python server-side decoder (`POST /cat-mode-decode-video`) had **no
representative fixtures**. These files fill that gap.

## How they were produced

Captured from the *real* production encode path — a `<canvas>` driven by the
same `getFrameState` protocol as `web_demo/templates/cat_mode.html`, recorded
with `MediaRecorder` (real VP8, variable frame rate), exactly what a browser
produces. Frame timing was held steady during capture so the videos are a clean,
deterministic reference (the decoder is sound on steady-timed video; real-device
timing jitter is a separate, capture-quality concern).

## Contents

| File | Blink speed | Payload | Expected decoded bits |
|------|-------------|---------|-----------------------|
| `cat_emptyhash_100ms.webm` | 100 ms | SHA-256("") | `e3b0c442…b855` (256 bits) |
| `cat_emptyhash_50ms.webm`  | 50 ms  | SHA-256("") | `e3b0c442…b855` (256 bits) |

`_decode_cat_video` returns the de-whitened payload bits; the test asserts they
equal the binary expansion of the empty-string SHA-256.

## Decoding (mirrors the production route)

The server route ffmpeg-converts the upload to MJPEG AVI @60fps, then decodes:

```bash
ffmpeg -y -i cat_emptyhash_100ms.webm -c:v mjpeg -q:v 2 -r 60 /tmp/x.avi
python -c "import sys; sys.path.insert(0,'web_demo'); from app import _decode_cat_video; \
print(_decode_cat_video('/tmp/x.avi')['binary'])"
```

The runnable check is `web_demo/test_cat_golden_decode.py` (needs `cv2` + `ffmpeg`).

## Regenerating

These are captured with a Puppeteer harness driving the production protocol; see
the project notes for the capture script. Regenerate only if the encode protocol
changes, and re-verify the decoded payload still matches before committing.
